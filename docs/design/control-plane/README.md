# Control-Plane Design

Implementation-facing notes for tracker-boundary placement, doctrine routing, and
operator control. These docs are non-normative, but several files are consumed
by coherence/drift checks as explanatory evidence.

- `ARCHITECTURE-MAP.md` — doctrine-to-operation map and active execution order.
- `EV-COHERENCE-OVERVIEW.md` — compact evidence-plane status snapshot.
- `DEVELOPMENT-META-LOOP.md` — canonical development workflow contract.
- `LIFECYCLE-COHERENCE-FLOWS.md` — schema lifecycle and gate-chain flow.
- `ATLAS.md` — site-of-sites staging note for cross-repo covers, seams,
  authority surfaces, projections, and descent conditions.
- `TOPOLOGY-V2.md` — shape-first placement model for authority objects,
  projections, repo hosts, and simplex-native tracker routing.
- `MEMORY-LANES-CONTRACT.md` — work-memory lane split and write discipline.
- `CONTROL-PLANE-THREAT-MODEL.md` — threat and hardening matrix.
